# Prodex 0.434.0

## Highlights

- Align the audited compatibility baseline with official Codex
  `rust-v0.159.0`, including the new opt-in `instant_interrupt` steering
  capability and item-anchored app-server thread pagination.
- Fix Super resume after an interrupted overlay when pasted text or attached
  media is still referenced through a deleted `.prodex-overlay-*` path.
  Resume now repairs the rollout to durable shared attachment paths before
  Codex reads it.
- Preserve the pre-migration Gemini stream identifier contract in the
  authoritative Mojo response kernel, restoring UUID-shaped text/media/citation
  item IDs without a Rust fallback.

## Codex 0.159.0 compatibility

Prodex keeps the new Codex behavior upstream-owned where possible:

- `instant_interrupt` remains opt-in and disabled by default unless the user
  or Codex configuration enables it.
- `thread/items/list` additive item-anchor cursors pass through unchanged.
- Internal tool metadata remains restricted to the upstream-approved
  first-party destinations. Codex 0.159 moved the gate into its model-provider
  boundary; Prodex updated its compatibility guard rather than weakening it.
- Explicit quota, balance/spend-limit, rate-limit, overload, and invalid-prompt
  error classes remain preserved after Codex moved failed-response
  classification into a dedicated SSE error module.
- Codex's TUI/session and Windows process-launch fixes remain upstream-owned.

## Resume attachment durability

A Super overlay is temporary, but pasted text and media must survive longer
than the overlay itself. Prodex now runs targeted session maintenance before a
direct resume and repairs stale attachment references to the durable shared
Codex storage. The path scanner also stops at JSON escape boundaries, so an
escaped newline between two attachment paths cannot become part of a
`pasted-text-*.txt` filename.

This applies to direct `prodex s <uuid>` resume and the same shared resume
repair path used by normal runtime launches.

## Release scope

This release publishes the standalone GitHub/container artifacts through the
repository release workflow. It does not publish npm or crates.io packages.
