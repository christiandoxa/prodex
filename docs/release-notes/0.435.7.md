# Prodex 0.435.7

## New Features

- No new command surface. This hotfix focuses on transparent quota recovery for long-running Codex turns and release compatibility.

## Bug Fixes

### Post-compaction quota exhaustion no longer leaks to the user while a ready profile exists

- Fix the regression where a Codex turn could compact successfully, keep an `x-codex-turn-state` affinity token, then surface `usage_limit_exceeded` from the exhausted owner even though another compatible profile remained ready.
- WebSocket post-compaction requests now classify turn-state-only hard affinity as recoverable when the request carries reconstructable full context and another route-eligible profile is available.
- Prodex marks the exhausted turn-state lineage dead, emits the existing retryable full-context replay signal, scrubs the stale turn-state token from the next handshake and `response.create` metadata, and lets the replay commit on the healthy profile.
- Responses HTTP receives the same safe replay treatment for reconstructable full-history requests.
- Requests that do not contain reconstructable full history remain fail-closed; Prodex does not blindly rotate context-dependent continuations or risk duplicating completed tool side effects.
- Pool exhaustion semantics are unchanged: quota is terminal only after the compatible pool is genuinely unusable, or when replay is unsafe or explicitly disabled.

### Release gates are synchronized with the current runtime source

- Fix Clippy `-D warnings` failures without adding warning allowances.
- Split oversized Rust adapter/test files rather than raising size thresholds, and ratchet the existing size cap downward.
- Refresh Mojo ownership and no-fallback self-test evidence to the actual current Mojo entry points while preserving the frozen baseline and canonical production-share metric.
- Update the exact sub-agent launcher rendering regression to match the hidden launcher command that is actually emitted.

## Compatibility Notes

### OpenAI tunnel-client 0.0.16

- Qualify official `openai/tunnel-client` v0.0.16 as the release-time latest-stable reference while keeping the runtime minimum at v0.0.13 plus the existing `run` capability check.
- The v0.0.16 release adds MCP response timing, optional W3C trace-context forwarding, and an OpenTelemetry dependency security update; Prodex does not enable the new trace-forwarding option by default.
- The official v0.0.16 tag resolves to commit `5f99daabd4aa4a77049e6d81d54a0d8c18335397`.
