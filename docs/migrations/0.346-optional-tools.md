# 0.346 Optional-Tool Migration

## What Changed

- Caveman is an external, versioned optional tool; no Caveman payload is linked
  into the Prodex binary.
- Super is the explicit YOLO entrypoint: it uses full access and invocation-local
  workspace/hook trust without prompting. Use `prodex run` for least privilege.
- Optional tools are selected with `--tool` and made strict with
  `--require-tool`.
- Exact and shadow Smart Context requests no longer mutate learned or persisted
  state. New artifacts use the `sc2:` SHA-256 schema. Valid scoped legacy
  records migrate on durable save; unscoped stores are quarantined because
  their tenant/profile/provider/workspace boundary cannot be proven.

## Required User Action

Move a user-managed Caveman checkout to
`<managed-root>/caveman/1.9.1/`, add the validated manifest documented in
[Optional Tools](../optional-tools.md), and run:

```bash
prodex capability super-doctor
prodex caveman --dry-run
```

Prodex never deletes or overwrites that installation.

## Compatibility Window

- Existing command aliases remain available.
- Leading legacy tool words are translated into typed selections for one
  release. Prefer `--tool <name>`.
- An unversioned `caveman/` or `ponytail/` managed directory is accepted only
  when its manifest and digest exactly match the vetted release. This fallback
  is scheduled for removal in 0.348.0.
- `prodex setup --verify-assets` remains an alias for
  `prodex setup --verify-tools` for one release.

Temporary overlays are reconciled idempotently. Reconciliation removes only
Prodex-owned legacy Caveman marketplace/plugin entries and an exact legacy
generated developer instruction. It does not change the global Codex home or
unrelated user configuration.

## Rollback Controls

- Caveman discovery: remove the tool from `--tool`/`--require-tool` or move the
  user-managed checkout outside the managed root. Prodex never deletes it.
- Super permissions: use `prodex run` instead. The `prodex s` / `prodex super`
  entrypoint intentionally enables full access and invocation-local workspace
  and hook trust.
- Smart Context: set `PRODEX_SMART_CONTEXT_CANARY_PERCENT=0` or launch without
  Smart Context. New requests become exact pass-through immediately; active
  streams and affinity bindings are unchanged.
- Persisted Smart Context state: stop the proxy before moving a scoped store
  and its key. Do not copy a store into another scope. A failed rollback is
  quarantined and reported degraded rather than loaded as empty healthy state.

## Residual Risks

| Severity | Owner/action | Residual |
| --- | --- | --- |
| Medium | Runtime launch: remove the unversioned discovery fallback in 0.348.0 | One-release Caveman/Ponytail compatibility paths remain accepted only with exact manifest and digest validation. |
| Medium | Runtime proxy: expand live-model evaluation before quality claims | Deterministic replay proves request invariants and tokenizer counts, not model task quality. |
| Low | Runtime proxy: keep corruption/retention doctor tests in release gates | Scoped artifact loss causes safe pass-through/degraded health, but removes reuse until rebuilt. |
| Low | CLI: delete leading positional translation after its stated release | Leading legacy tool words remain temporarily ambiguous; later tool-like arguments are preserved verbatim. |
