# 0.346 Optional-Tool Migration

## What Changed

- Caveman is an external, versioned optional tool; no Caveman payload is linked
  into the Prodex binary.
- Super is least-privilege by default. Use `--full-access` only when intended.
- Optional tools are selected with `--tool` and made strict with
  `--require-tool`.
- Exact and shadow Smart Context requests no longer mutate learned or persisted
  state. New artifacts use the `sc2:` SHA-256 schema; verified legacy `sc:`
  records are read and migrated, but new legacy identifiers are not emitted.

## Required User Action

Move a user-managed Caveman checkout to
`<managed-root>/caveman/1.9.1/`, add the validated manifest documented in
[Optional Tools](../optional-tools.md), and run:

```bash
prodex capability super-doctor
prodex caveman --dry-run
```

Prodex never deletes or overwrites that installation.

## Compatibility Window

- Existing command aliases remain available.
- Leading legacy tool words are translated into typed selections for one
  release. Prefer `--tool <name>`.
- An unversioned `caveman/` or `ponytail/` managed directory is accepted only
  when its manifest and digest exactly match the vetted release. This fallback
  is scheduled for removal in 0.348.0.
- `prodex setup --verify-assets` remains an alias for
  `prodex setup --verify-tools` for one release.

Temporary overlays are reconciled idempotently. Reconciliation removes only
Prodex-owned legacy Caveman marketplace/plugin entries and an exact legacy
generated developer instruction. It does not change the global Codex home or
unrelated user configuration.
